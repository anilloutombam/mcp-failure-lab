# MCP Failure Lab 0.10.0 duplicate-response compatibility report

Tested on 2026-09-19 against the published `mcp-failure-lab@0.10.0` npm package.

## Release identity

- npm package: `mcp-failure-lab@0.10.0`
- npm integrity: `sha512-9BLArjh99frHkXjFNt4A3wgI1r7MxUz9bsVlSjmLfGR25uPXPkmfR6tupwDnywcUSIR3SREimPbYKDgUnYg5iw==`
- Fault: `duplicate_response`
- Transports: stdio and Streamable HTTP

## Method

Each client started or connected to the published package, called `duplicate_response`, waited for
the second response to be processed, and called `ping` on the same session. A passing recovery
check required `ping` to return a successful tool result.

The stdio server was launched with:

```text
npx -y mcp-failure-lab@0.10.0 serve
```

The HTTP cases used the same published package on a loopback Streamable HTTP endpoint.

## Results

| Client     | stdio | Streamable HTTP | Observable duplicate behavior                        | Same-session `ping` |
| ---------- | ----: | --------------: | ---------------------------------------------------- | ------------------: |
| TypeScript |  Pass |            Pass | Error callback reported a response for an unknown ID |                Pass |
| Python     |  Pass |            Pass | No call-level duplicate error surfaced               |                Pass |
| Go         |  Pass |            Pass | No call-level duplicate error surfaced               |                Pass |
| Rust       |  Pass |            Pass | No call-level duplicate error surfaced               |                Pass |
| C#         |  Pass |            Pass | No call-level duplicate error surfaced               |                Pass |

The TypeScript SDK accepted the first result, then reported the repeated response through its error
callback because the request ID was no longer pending. The diagnostic did not close the session.

Python, Go, Rust, and C# returned the first result without a call-level error and completed the
following `ping`. The harnesses did not instrument private SDK internals, so this result does not
prove whether those clients silently discarded the duplicate or recorded it internally.

## Scope

This is a focused duplicate-response check, not a repeat of the full 0.9.0 compatibility matrix.
It does not cover every SDK version or host application. The earlier delay, timeout, cancellation,
malformed-response, and disconnect results remain documented in the
[0.9.0 report](v0.9.0.md).
